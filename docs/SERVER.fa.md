# نصب روی سرور و مصرف منابع

نصب‌کننده برای Ubuntu 22.04 و جدیدتر، Debian 12 و جدیدتر، پردازندهٔ x86_64 یا ARM64 و یک میزبان با systemd طراحی شده است. در کانتینر معمولی بدون systemd اجرا نمی‌شود. برای نصب اولیه، دسترسی خروجی به GitHub، PyPI و سرورهای دانلود Python لازم است؛ هنگام اجرا، دسترسی به Cloudflare API، Telegram API و خوراک NetBlocks لازم است.

## نصب با یک دستور

با یک کاربر دارای sudo:

```sh
curl -fsSL https://raw.githubusercontent.com/yasinmalek82/monitor_internet_traffic/main/install.sh | sudo bash
```

اگر root هستید:

```sh
curl -fsSL https://raw.githubusercontent.com/yasinmalek82/monitor_internet_traffic/main/install.sh | bash
```

نصب‌کننده Python مستقل و نسخه‌های قفل‌شدهٔ وابستگی‌ها را در پوشهٔ خودش نصب می‌کند. Python و پکیج‌های سایر برنامه‌ها، Nginx، Docker، فایروال، cron و سرویس‌های دیگر را تغییر نمی‌دهد. اگر curl یا گواهی‌های ریشهٔ TLS موجود نباشند، فقط همان پیش‌نیازها با apt نصب می‌شوند؛ ارتقای عمومی سیستم انجام نمی‌شود. بسته‌های محاسباتی از wheel نصب می‌شوند و کامپایل C/C++ روی سرور انجام نمی‌شود.

توکن BotFather و توکن خواندن Radar به‌صورت مخفی خوانده می‌شوند. برای دریافت شناسهٔ چت، ابتدا در چت خصوصی ربات خودتان `/start` بفرستید، سپس هنگام درخواست شناسه، `find` را وارد و شناسهٔ خودتان را انتخاب کنید. چت دیگران یا گروه را انتخاب نکنید.

قبل از راه‌اندازی، توکن‌ها و قالب پاسخ Radar بررسی می‌شوند. حساب سرویس اختصاصی `iran-monitor` است و ربات با root اجرا نمی‌شود. اگر `check` شکست بخورد، سرویس نسخهٔ تازه راه‌اندازی نمی‌شود و خطا نمایش داده می‌شود.

## مدیریت

```sh
sudo iran-monitor status
sudo iran-monitor logs
sudo iran-monitor follow
sudo iran-monitor resources
sudo iran-monitor check
sudo iran-monitor configure
sudo iran-monitor restart
sudo iran-monitor stop
sudo iran-monitor start
sudo iran-monitor update
```

`configure` فقط سرویس همین برنامه را موقتاً متوقف می‌کند تا دریافت پیام Telegram با نمونهٔ فعال تداخل نداشته باشد. در صورت موفق بودن تنظیم و بررسی اتصال، سرویس شروع می‌شود؛ در صورت شکست، تنظیم قبلی بازگردانده می‌شود.

برای گرفتن نمودار آزمایشی روی خود سرور، بدون تماس با Telegram:

```sh
sudo iran-monitor demo
```

خروجی در `/var/lib/iran-internet-monitor/demo` است و برچسب «دادهٔ ساختگی» دارد.

## مصرف و محدودیت منابع

| بخش | رفتار |
|---|---|
| پایش | یک فرایند Python؛ بدون بارگذاری Matplotlib و NumPy |
| دریافت داده | Radar هر ۵ دقیقه؛ منابع مکمل هر ۳۰ دقیقه |
| دریافت دستور Telegram | long polling با انتظار ۲۰ ثانیه در سمت Telegram؛ حلقهٔ محاسباتی مداوم ندارد |
| نمودار | یک فرایند موقت؛ حداکثر ۶۰ ثانیه زمان؛ با اتمام کار حافظه‌اش آزاد می‌شود |
| نمودار تکراری | تنها آخرین PNG در حافظه نگه داشته می‌شود و دوباره پردازش نمی‌شود |
| حافظهٔ کل سرویس | `MemoryHigh=128M` و `MemoryMax=256M` شامل پردازش نمودار |
| CPU کل سرویس | `CPUQuota=20%` یعنی حداکثر یک‌پنجم یک هسته، نه ۲۰٪ کل CPU چند‌هسته‌ای |
| اولویت | `Nice=10`، وزن CPU پایین و اولویت I/O بیکار |
| رشته‌ها و فرایندها | محاسبات NumPy تک‌رشته‌ای؛ سقف مجموع taskها ۳۲ |
| دیسک | یک snapshot، حداکثر ۱۰۰ رخداد، حداکثر دو نسخهٔ کد؛ کش نصب موقت پاک می‌شود |
| شبکهٔ ورودی | پورت باز نمی‌شود؛ فقط اتصال خروجی |

`MemoryHigh` آستانهٔ فشار حافظه است و `MemoryMax` سقف نهایی، نه پیش‌بینی مصرف معمول. این کنترل‌ها به پشتیبانی cgroupهای حافظه و CPU روی میزبان وابسته‌اند. [مستندات systemd](https://www.freedesktop.org/software/systemd/man/latest/systemd.resource-control.html)

در اندازه‌گیری محلی macOS، RSS فرایند پایش حدود ۲۹ MiB و حداکثر RSS پردازش موقت نمودار حدود ۸۱ MiB بود؛ این عدد تضمین مصرف Linux یا سرور شما نیست. دستور `resources` مصرف واقعی سرویس سرور را نشان می‌دهد. آزمون CI روی Ubuntu، تولید نمودار را با محدودیت‌های واقعی سرویس هم اجرا می‌کند. اجرای دوبارهٔ اندازه‌گیری بدون توکن از checkout:

```sh
uv run --locked python scripts/measure_resources.py
```

برای نصب، حدود ۱ GiB فضای آزاد برای دانلود، محیط مستقل و آماده‌سازی نسخهٔ جدید در نظر بگیرید. محدودیت‌های systemd مربوط به اجرای سرویس‌اند؛ نصب و دانلود اولیه موقتاً منابع جداگانه مصرف می‌کنند. روی سرور شلوغ، ابتدا `free -h` و `df -h /opt` را ببینید. اگر فضای آزاد کافی برای همین سقف‌ها ندارید، بهتر است پایش روی سرور دیگری باشد.

اگر پردازش نمودار شکست بخورد یا از مهلت بگذرد، هشدار به‌صورت متن فرستاده می‌شود. سقف منابع، دسترس‌پذیری بی‌قیدوشرط را تضمین نمی‌کند؛ رخداد OOM می‌تواند باعث راه‌اندازی دوبارهٔ سرویس شود.

## به‌روزرسانی، بازگشت و نگهداری

نسخهٔ جدید در پوشه‌ای جدا ساخته می‌شود و تا آماده و بررسی شدن آن، نسخهٔ قبلی به کارش ادامه می‌دهد. هنگام فعال‌سازی فقط سرویس همین برنامه restart می‌شود. نسخهٔ قبلی کد نگه داشته می‌شود و شکست خود دستور شروع سرویس، در صورت وجود نسخهٔ قبلی، کد را برمی‌گرداند. خرابی‌هایی که بعداً رخ دهند خودکار rollback نمی‌شوند؛ وضعیت را با `status` و `logs` بررسی کنید.

برای نصب/به‌روزرسانی یک tag یا commit مشخص:

```sh
sudo iran-monitor update --ref v0.1.0
```

برای آماده‌سازی بدون سؤال و بدون شروع سرویس، از نسخهٔ دانلودشدهٔ نصب‌کننده استفاده کنید:

```sh
sudo bash install.sh --no-start
sudo iran-monitor configure
```

برای نصب از checkout محلی، بدون دانلود سورس از GitHub:

```sh
sudo bash install.sh --source /absolute/path/to/checkout --no-start
```

برای دیدن برنامهٔ نصب بدون تغییر سیستم، روی هر دستگاه:

```sh
bash install.sh --dry-run
```

مسیرهای ثابت:

| مسیر | محتوا |
|---|---|
| `/opt/iran-internet-monitor/current` | لینک نسخهٔ فعال |
| `/opt/iran-internet-monitor/releases` | نسخهٔ فعال و قبلی، به همراه محیط Python هرکدام |
| `/opt/iran-internet-monitor/python` | Python مستقل مدیریت‌شده |
| `/etc/iran-internet-monitor/monitor.env` | توکن‌ها؛ فقط root و گروه سرویس دسترسی خواندن دارند |
| `/var/lib/iran-internet-monitor` | SQLite و وضعیت هشدارها |
| `/var/cache/iran-internet-monitor` | کش فونت‌ها |
| `/etc/systemd/system/iran-internet-monitor.service` | واحد سرویس |

برای backup، سرویس را متوقف و فایل تنظیمات و کل پوشهٔ داده را با دسترسی محدود کپی کنید. بعد سرویس را شروع کنید. روی دو سرور هم‌زمان همان توکن را اجرا نکنید؛ Telegram دریافت هم‌زمان با polling را نمی‌پذیرد.

حذف سرویس و کد، با حفظ تنظیمات، داده و کش برای بازیابی:

```sh
sudo iran-monitor uninstall
```

هیچ برنامه یا سرویسی از بقیهٔ سرور حذف نمی‌شود. برای حذف داده‌های باقی‌مانده، ابتدا backup بگیرید و مسیرهای مخصوص همین برنامه را جداگانه بررسی کنید.
